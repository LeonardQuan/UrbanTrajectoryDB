# 第四步：验证纬度取值范围

日期：2026-10-07

## 这一步的目标

第三步验证纬度是否能转换成数字。本步骤继续验证转换后的数字是否是合法纬度。

纬度合法范围为：

```text
-90 ≤ latitude ≤ 90
```

因此`91.0`和`-91.0`虽然都是合法浮点数，但不是合法纬度。

## 第一轮RED→GREEN：检查上界

测试期望：

```text
line 7: latitude 91.0 out of range [-90, 90]
```

实现前解析器会接受`91.0`并创建轨迹点，因此pytest报告：

```text
Failed: DID NOT RAISE ValueError
```

先实现上界检查后，该测试通过。

## 第二轮RED→GREEN：检查下界

为了避免只实现上界而遗漏下界，我们再加入`-91.0`测试。只检查`latitude > 90`时，该测试失败，因为程序没有抛出异常。

最终实现：

```python
if not -90 <= latitude <= 90:
    raise ValueError(
        f"{path}: line {line_number}: "
        f"latitude {latitude} out of range [-90, 90]"
    )
```

## 需要搞懂的内容

### 数字合法不等于业务合法

`float("91.0")`能正常得到`91.0`，说明它是合法数字，但地理纬度不能超过90。

### Python链式比较

```python
-90 <= latitude <= 90
```

等价于：

```python
-90 <= latitude and latitude <= 90
```

### `not`

合法范围表达式为真时不报错；使用`not`后，只有不在范围内时进入异常分支。

### 边界

当前条件将`-90`和`90`视为合法值，因为使用的是`<=`。本步骤测试了上下界之外的值，边界值测试可以在后续补充。
