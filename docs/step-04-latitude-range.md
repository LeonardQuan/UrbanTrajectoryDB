# 第四步：验证纬度取值范围

日期：2026-10-07

## 这一步的目标

第三步验证纬度是否能转换成数字。本步骤继续验证转换后的数字是否是合法纬度。

纬度合法范围为：

```text
-90 ≤ latitude ≤ 90
```

因此`91.0`和`-91.0`虽然都是合法浮点数，但不是合法纬度。

## 第一轮RED→GREEN：检查上界

测试期望：

```text
line 7: latitude 91.0 out of range [-90, 90]
```

实现前解析器会接受`91.0`并创建轨迹点，因此pytest报告：

```text
Failed: DID NOT RAISE ValueError
```

先实现上界检查后，该测试通过。

## 第二轮RED→GREEN：检查下界

为了避免只实现上界而遗漏下界，我们再加入`-91.0`测试。只检查`latitude > 90`时，该测试失败，因为程序没有抛出异常。

最终实现：

```python
if not -90 <= latitude <= 90:
    raise ValueError(
        f"{path}: line {line_number}: "
        f"latitude {latitude} out of range [-90, 90]"
    )
```

## 需要搞懂的内容

### 数字合法不等于业务合法

`float("91.0")`能正常得到`91.0`，说明它是合法数字，但地理纬度不能超过90。

### Python链式比较

```python
-90 <= latitude <= 90
```

等价于：

```python
-90 <= latitude and latitude <= 90
```

### `not`

合法范围表达式为真时不报错；使用`not`后，只有不在范围内时进入异常分支。

### 边界

当前条件将`-90`和`90`视为合法值，因为使用的是`<=`。本步骤测试了上下界之外的值，边界值测试可以在后续补充。

## 必会问题与参考回答

### 1. 为什么91.0能转换成功，却仍是错误数据？

`float()`只检查字符串能否转换成浮点数，不检查地理业务规则。`91.0`可以转换，但超过纬度上界90，所以不能作为合法纬度。

### 2. 纬度的合法范围是什么？

`[-90, 90]`，即大于等于-90且小于等于90，两端都包含。

### 3. 链式比较是什么意思？

`-90 <= latitude <= 90`表示同时满足上下界要求。对于这里的数值变量，等价于`latitude >= -90 and latitude <= 90`。

### 4. not的作用是什么？

范围比较表示合法，`not`将结果取反。只有不合法时，条件才为真并进入报错分支。

### 5. 为什么使用<=而不是<？

因为-90和90本身也是合法纬度。严格小于会错误排除边界。

### 6. 为什么分别测试91.0和-91.0？

上界测试不能证明下界检查也正确。若只写`latitude > 90`，上界测试能通过，但下界错误会漏掉。

### 7. 为什么使用ValueError？

输入值能读取，也能转换，但不符合要求，属于值错误，而不是下标错误或文件权限错误。

### 8. raise后还会创建轨迹点吗？

不会。异常中断当前正常执行流程，后面的`points.append()`不再执行。当前函数向调用者传播异常，也不会返回已累积的列表。

### 9. pytest.raises()验证什么？

验证代码块是否抛出预期类型的异常。这里预期`ValueError`；没有异常或抛出其他类型都会导致测试失败。

### 10. match验证什么？

用正则表达式搜索异常信息是否包含预期内容，验证行号、错误值和合法范围。不要求整个异常消息与模式完全相等，所以前面的文件路径可以保留。

### 11. 为什么小数点需要转义？

正则中的`.`通常匹配任意单个非换行字符，`\.`才匹配字面上的小数点。因此测试写`91\.0`。

### 12. 为什么方括号需要转义？

正则中的方括号用于字符集合。要匹配错误信息中的普通方括号，需要写`\[`和`\]`，例如`\[-90, 90\]`。

### 13. 第三步和第四步有什么区别？

第三步检查能否转换成数字；第四步检查数字是否符合纬度规则。格式正确不代表业务合法。

### 14. 为什么还要运行以前的测试？

为了确认新代码没有破坏正常解析、字段数量检查和非数字纬度处理。这属于回归验证。
