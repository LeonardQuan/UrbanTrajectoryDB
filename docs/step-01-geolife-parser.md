# 第一步：解析一个 GeoLife 轨迹文件

日期：2026-10-02

## 这一步的目标

把一个文本形式的 GeoLife `.plt` 文件转换成 Python 中可以继续处理的轨迹点对象。

输入：

```text
39.984702,116.318417,0,492,39744.1201851852,2008-10-23,02:53:04
```

输出概念：

```python
TrajectoryPoint(
    latitude=39.984702,
    longitude=116.318417,
    altitude_feet=492.0,
    recorded_at=datetime(2008, 10, 23, 2, 53, 4),
)
```

## 我们实际完成了什么

### 1. 创建最小测试数据

文件：`tests/fixtures/sample_geolife.plt`

它包含 GeoLife 格式的 6 行文件头和 2 个轨迹点。测试使用小文件，是为了让输入固定、结果容易人工检查，不受完整数据集大小和网络下载影响。

### 2. 先写自动化测试

文件：`tests/test_geolife.py`

测试规定了解析器应该：

- 返回两个轨迹点；
- 正确读取纬度；
- 正确读取经度；
- 正确读取海拔；
- 把日期和时间转换成 `datetime` 对象。

第一次运行测试时出现：

```text
ModuleNotFoundError: No module named 'urban_trajectory_db.geolife'
```

这是我们预期的失败，因为功能当时还不存在。它证明测试确实能检测到缺失的功能。

### 3. 实现最小解析器

文件：`src/urban_trajectory_db/geolife.py`

实现包含：

- `TrajectoryPoint` 数据类；
- `parse_geolife_file()` 函数；
- 跳过前 6 行文件头；
- 逐行拆分逗号分隔字段；
- 把数字字符串转换为 `float`；
- 把日期和时间转换为 `datetime`；
- 返回轨迹点列表。

### 4. 重新运行验证

结果：

```text
1 passed
All checks passed!
```

同时验证了：

- pytest 测试通过；
- Ruff代码检查通过；
- Docker Compose配置语法通过。

## 你需要搞懂什么

### Python部分

1. `Path` 为什么比手动拼接字符串路径更可靠；
2. `with path.open(...) as file` 为什么会自动关闭文件；
3. `for _ in range(6)` 为什么用于跳过文件头；
4. `line.strip()` 删除了什么；
5. `split(",")` 如何把一行拆成字段列表；
6. `float(...)` 为什么用于经纬度和海拔；
7. `datetime.strptime(...)` 如何按照格式解析时间；
8. `list[TrajectoryPoint]` 类型标注表达什么；
9. `@dataclass` 帮我们自动生成了什么；
10. `frozen=True` 和 `slots=True` 的基本作用。

### 测试部分

1. 为什么测试要先于实现；
2. 为什么第一次失败是好事；
3. fixture测试文件和 pytest fixture 不是同一个概念；
4. `assert len(points) == 2` 在验证什么；
5. 为什么不直接使用完整GeoLife数据集测试；
6. 测试通过只能证明当前已覆盖行为，不能证明程序处理了所有异常情况。

### 数据部分

1. 纬度与经度的顺序不能颠倒；
2. GeoLife文件前6行是元数据，不是轨迹点；
3. GeoLife海拔字段通常以英尺表示；
4. 当前解析出的时间没有时区信息；
5. 当前版本还没有检查经纬度是否合法，也没有处理损坏数据。
